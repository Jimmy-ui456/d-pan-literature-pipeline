# 架构

源码、配置、测试和打包信息只有一个维护位置：本 Git 仓库根目录。原研究工作区中的兼容入口加载这里的实际模块，不保存另一套实现。`scripts/build_release.py` 从白名单输入生成隔离暂存区、源码 ZIP、wheel、sdist 及逐文件哈希清单；`dist/` 和 `.validation/` 均为可重建生成物，不参与源码同步。见 [RELEASING.md](RELEASING.md)。

管线按以下顺序处理记录：输入（联网数据源或离线 JSON）→ 规范化、分类与去重 → 身份核验 → PDF 关联及身份比对 → 证据卡和结果段定位 → 人工审阅门禁。

`litsearch.sources` 取得源记录；`core` 负责去重、范围筛选、规则分类和提取候选文字；`verification` 使用本地元数据快照并在明确请求时访问权威源；`pdfs` 关联本地 PDF、可选下载并检查身份；`evidence` 生成证据卡、审阅模板并只接纳满足门禁的人工决定；`outputs` 写入审计、表格和审核材料。`cli` 编排这些模块，并为每次运行建立独立输出目录。

独立工具入口 `service_probe` 验证显式请求的真实服务合同，`discovery` 处理同义词检索及引用图，`document_parse` 解析本地表格并在明确启用时调用 OCR。它们保留单独的来源、预算和失败记录，输出不自动替代 `evidence` 的证据卡或人工决定。具体安装、命令与状态见 [ENGINEERING_TOOLS.md](ENGINEERING_TOOLS.md)。

身份核验状态、PDF 身份状态和人工审阅状态是独立字段。导入 JSON 时，旧的派生与信任字段会清空，避免把先前输出当作新的权威证据。没有匹配的人工审阅文件时，记录保持待审；有审阅文件也仍需通过身份、文档类型和证据门禁。

`litsearch_zotero` 是可选的本机工具：它依赖核心的数据模型和分类函数，但核心从不导入 Zotero 扩展。这样离线演示和普通文献处理不需要接触本机 Zotero。
